# Публикация annalankina.ru

Эталон — текущие локальные файлы сайта. Для публикации нужно отправлять весь
подготовленный набор исходников вместе с новыми изображениями и компонентами.
Загрузка только App.tsx или только styles.css оставит сайт неполным.

## Как устроена публикация

- Репозиторий: https://github.com/lankina-2004-ui/my-site
- Домен обслуживается GitHub Pages.
- После отправки в main запускается `.github/workflows/main.yml`.
- Сборка: `pnpm install --frozen-lockfile`, затем `pnpm build`.
- На GitHub Pages отправляется только `dist` через upload-pages-artifact.
- Адрес файлов сборки начинается с `/`, поскольку используется собственный домен.
- `dist/404.html` сохраняет открытие существующих прямых адресов проектов.
  На GitHub Pages такой переход получает HTTP 404, но приложение отрисовывает
  страницу. Ссылки вида `/#/gramy` открываются с HTTP 200.
- `dist/build-info.json` позволяет проверить точный состав опубликованной сборки.

## Что делать владельцу сайта

Код самостоятельно редактировать не нужно. Подготовленная версия ещё не отправлена.
Подтвердите в чате: «Разрешаю отправить подготовленные изменения и опубликовать сайт».
После отправки в main публикация запускается автоматически.

Чтобы увидеть результат публикации:

1. Откройте https://github.com/lankina-2004-ui/my-site/actions
2. Нажмите последний запуск «Deploy site to GitHub Pages».
3. Дождитесь зелёных отметок у build и deploy.
4. Откройте https://annalankina.ru/ и обновите страницу.

Повторный запуск старой сборки через Run workflow до отправки новых исходников
не перенесёт локальные правки на сайт.

## Проверка перед публикацией

`pnpm build` и `pnpm preview --host 127.0.0.1 --port 4173` позволяют проверить
готовую сборку. Она должна совпадать с локальным сервером на порту 5173.
Никакие исходники в `src` для настройки публикации менять не требуется.
